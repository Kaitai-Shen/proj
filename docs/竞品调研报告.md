# LectureCast 竞品调研报告

- 调研日期：2026-11-19
- 调研范围：① 2026 Qoder 高校创造力大赛（天池 532536）StudyHack 赛道已发布作品帖；② 市面上 AI 教学/讲解视频生成产品；③ 外部技术方案文档的 Qoder Sites 可行性评估（第五节）
- 调研目的：为 LectureCast（知识点 → 三智能体生成教学动画 + TeachQuiz）找出与优秀作品的差距，指导赛前打磨优先级
- 性质：仅调研，不含实施

---

## 一、比赛内竞品（评委视角完全相同）

### 1. 费曼检查器（StudyHack，杭州电子科技大学，170 浏览）

**定位**：讲解自检器 — 你把概念讲一遍，它指出哪里没讲清，追问、复查、重讲，生成可分享的费曼卡片。

**比我们好的地方**：

| 维度 | 它的做法 | 我们的差距 |
| --- | --- | --- |
| 评委零配置（最关键） | 硬要求"点开链接就能用"：**服务端代理调模型，前端不出现 Key / 模型名 / baseURL** | 我们要求评委自带 API Key，体验门槛高 |
| 三层降级架构 | L1 预置回放（离线可跑）→ L2 本地规则粗检（断网兜底）→ L3 联网完整模式；**失败静默降级（角标切换），不弹错不拦流程** | 我们只有"演示模式 / 报错"两态 |
| LLM 输出校验闭环 | 卡片过 schema 校验 + 引用必须是讲稿连续子串；失败带错误信息重试一次，再失败剔除并注明 | 我们对 LLM 输出只有编译校验，无语义校验 |
| 可分享产物 | 1080 宽竖版 PNG 卡片（含分数对比、知识图谱），可下载、可复制带比赛标签的分享文案 | 我们没有任何可分享产物 |
| 内容深度 | 5 条预置回放 + 10 个常用概念入口 | 我们只有 1 个演示案例 |
| 帖子写法 | Qoder 过程写成"6 轮主任务，每轮先给验收口径，按读数驳回"；诚实说明边界（本地模式看不了什么明说） | 我们还没有作品帖素材积累 |

**值得抄的架构事实**：它证明在 Qoder Sites 上做"服务端代理调模型"可行且效果好 — Sites Function + Secret 存团队 Key + 失败降级，评委全程无感。

### 2. 别搞混 · Confusion Clinic（StudyHack，167 浏览）

**定位**：易混概念辨析训练 — "不只告诉你答错了，还画出你是哪根线搭错了"。

**比我们好的地方**：

- **手写内容深度**：27 对易混概念、33 道辨析题、65 条**手写错误模型**、7 个章节簇 — 评委看重精心打磨的内容，而非 AI 生成数量
- **诊断闭环**：答错 → 错误连线可视化（红虚线误解 / 绿线修正）→ 同章节定向重练 → 考前速览导出 Markdown/打印
- **真实浏览器量测**的开发流程：每轮修改后执行交互和几何断言（节点越界、标签重叠、窄屏溢出、控制台错误）
- **帖子写法**：每张截图配一段"创新如何落到真实界面"的叙事，先讲创新点再指截图证据

### 3. 交互类作品（二阶系统仿真、化学实验等）

共同点：**用户可拖拽、可动手**。我们的教学视频是单向被动观看 — TeachQuiz 是正确的补救方向，但只在片尾触发。

## 二、市场竞品（外部产品）

| 产品 | 一句话定位 | 输入→输出 | 等待 | 强于我们 | 弱于我们 |
| --- | --- | --- | --- | --- | --- |
| NotebookLM Video Overviews（Google） | 文档→口播幻灯视频 | ≤50 个来源→1-6 分钟旁白视频，6 种视觉风格 | 2-5 分钟 | 多文档综合、中文配音、免费额度（3 个/天）、大厂信任 | 本质是幻灯片+旁白，画不了精确的向量/算法动画；不能编辑帧；视频与测验割裂 |
| Manimator（开源） | 文本/PDF/arXiv→Manim 动画 | "把 arXiv 链接换域名"玩法传播 | 25 秒~几分钟 | 开源、已有流量、输入形式丰富 | 单次生成无视觉审查、失败率高、无配音无测验 |
| Code2Video 官网（论文方） | 论文展示站 | 仅 10 个预渲染视频 + 与 Veo3/Wan 对比 | —（无法在线试用） | 学术权威性 | **无在线试用**（生成需数十分钟）— 我们"浏览器当场跑"是最大差异化 |
| Generative Manim / manim-agent / Vismo | 开源 Manim 生成器 | 文本→Manim（部分带配音） | 分钟级 | 配音、多语种 | 无修正循环、无测验、需自部署 |
| Gamma / Synthesia / HeyGen / Khanmigo | 演示/数字人/辅导 | 各自场景 | — | 商业化成熟、落地页强 | 与"精确知识动画"不在同一赛道 |

**落地页 30 秒法则**（Gamma 实践）：hero = 自动播放的成品示例 + "立即试一个"输入框。我们的 Landing 只有输入框，缺自动播放的成品动画。

## 三、评委最可能挑战我们的 3 个点

1. **"为什么让我填 API Key？"** — 费曼检查器已证明托管模式可行。BYOK 应降级为"进阶自定义"，默认走官方托管（Sites Function 代理 + 团队 Key 放 Secret + 限额）。
2. **"看视频不如玩交互仿真？"** — 防守：TeachQuiz 是论文验证过的学习效果闭环 + Critic 修正过程可视化是独有卖点；可考虑"边看边出题"增强交互感。
3. **"生成质量/可靠性？"** — 防守：分段渲染 + 实时预览 + Critic 自我修正（Manimator 式单发做不到）；视频控制 60-90 秒；演示案例保底质量。

## 四、按优先级排序的行动建议

| 优先级 | 行动 | 说明 |
| --- | --- | --- |
| P0 | 官方托管模式 | Edge Function 代理调用 + 团队 Key 放 Sites Secret + 每日限额；评委免 Key 完整体验。与赛道优秀作品对齐的最低门槛 |
| P1 | 演示内容扩容 | 预置案例 1 → 3-4 个（覆盖数学/物理/CS）；Landing hero 改为自动播放成品动画 + 输入框 |
| P2 | 可分享产物 | 复用已有 html2canvas 导出"学习报告卡"（知识点 + 测验得分 + 视频截图长图 PNG），带比赛标签 |
| P3 | 作品帖质量 | 按费曼/别搞混标准：轮次 + 验收口径的 Qoder 过程叙事、截图配叙事、诚实边界说明 |
| P4 | Critic 前后对比可视化 | 修正前/后帧并排展示，强化"自我修正"卖点 |
| P5 | LLM 输出语义校验 | 借鉴费曼的 schema 校验 + 重试/剔除闭环 |

## 五、AI Tutor Video 技术设计文档评估（Qoder Sites 可行性）

> 评估对象：`AI_Tutor_Video_技术设计文档 (1).md`（V2.0，2026-11-19）。基于 Code2Video 的服务端渲染方案：Planner→Coder→Critic + 中文 TTS + 字幕 + FFmpeg 合成 MP4，异步任务队列 + SQLite + Docker 隔离渲染。文档自述核心原则：「Qoder Sites 是公开参赛入口；Python/Manim 渲染服务独立部署」。

### 5.1 逐层可行性判定（依据 Sites 运行时实测边界）

| 文档所需能力 | Qoder Sites 实际情况 | 判定 |
| --- | --- | --- |
| React + TypeScript + Vite 静态前端 | ✅ 静态产物 + SPA，LectureCast 已在用 | **可行** |
| Edge Function 做 VideoGenerationGateway 代理 | ✅ Deno/TS HTTP handler，与已实现的 relay 同模式 | **可行** |
| FastAPI 后端（Python 3.11） | ❌ Edge Function 仅支持 Deno/TS，无 Python 运行时 | **不可行** |
| 常驻 Worker 进程 + 轮询数据库 | ❌ 平台要求 HTTP handler 模式，「而非启动命令或持久后台进程」，单请求秒级超时 | **不可行** |
| Docker 隔离渲染 Manim（分钟级长任务） | ❌ 无容器能力、无长任务执行环境 | **不可行** |
| FFmpeg 合成 / 中文 TTS（服务端） | ❌ 同上 | **不可行** |
| 视频工件存储 + Range 播放 | ⚠️ Storage SDK 签名 URL 可行，但大文件经 Function 中转受限 | 勉强 |

**结论：前端能在 Qoder Sites 跑；生成引擎（FastAPI + Docker Manim + TTS + FFmpeg）跑不了，必须外部 Linux 服务器。文档 §0.1 的自判与此一致，判断正确。**

### 5.2 与 LectureCast 现状对照

| 维度 | AI Tutor Video 方案 | LectureCast 现有实现 |
| --- | --- | --- |
| 渲染方式 | 服务端 Manim（Docker 隔离） | 浏览器 Remotion 实时渲染 |
| 输出形态 | MP4 + 中文配音 + 字幕 | 浏览器播放（暂无配音） |
| Key 管理 | 服务端 Secret（评委零配置） | BYOK 本地存储（评委有门槛） |
| 部署依赖 | 外部 Linux 服务器 + Docker Compose | 纯 Qoder Sites，已就绪 |
| TeachQuiz | 明确不在第一期范围 | 已实现（论文同款指标） |
| 智能体过程展示 | 任务状态轮询（进度条） | 三智能体实时直播（差异化卖点） |
| 当前进度 | 未编码，5 项前置确认未落实 | 已开发完成并本地验证 |

### 5.3 时间线风险（决定性因素）

- 文档排期 W0–W6 ≈ 6 周；**报名+发帖截止 11-30 18:00，仅剩 11 天**；初筛 12-01 开始。
- 文档 §14 要求编码前确认的 5 项（实验室代码、LLM/VLM/TTS API 配额、开发机、Docker 资源限制、公式/时间戳兼容测试）均未落实。
- 走外部服务器路线还需：云主机采购、§8 安全隔离（不可省略）、HTTPS/CORS 验证、评委网络可达性测试 — 均超出窗口。
- 文档 P-1 里程碑（公开站点、HTTPS API、CORS、播放示例 MP4）**LectureCast 已全部完成**。

### 5.4 结论与吸收计划

**不推翻现有架构**（时间不够、重复建设、比赛评审对象是 Sites 站点本身）。吸收其三个增量点，与第四节行动项合并执行：

| 增量点 | 对应行动 | 说明 |
| --- | --- | --- |
| 中文 TTS 旁白 + 字幕轨 | 新增（P2 级） | Planner narration 接浏览器 Web Speech 或 TTS API；顺带补齐 NotebookLM 对比中「中文配音」短板 |
| MP4 导出 | 新增（P3 级） | 逐帧捕获 + WebCodecs；产出可分享产物 |
| 工件可下载（分镜 JSON / 生成代码） | 新增（P4 级） | 借鉴其产物可追溯思想 |

另：该文档的「服务端代理调模型」思想与本报告 P0 行动项（官方托管模式）同构 — Edge Function 代理 + 团队 Key 放 Secret，合并执行。

赛后若获得服务器资源，可按该文档路线（外部 FastAPI + Manim Docker）补齐服务端真渲染与配音合成，作为 P3 科研扩展。
